# ADR-0003 テストの基盤

- 状態：採用（2026-11-21）
- 関係する書類：要件定義・基本設計書 第7章（決定5）、詳細設計書 第9章、README

## 状況

ベアメタルのファームウェアを、実機なしで（P1〜P4）、あとから実機とシミュレーターでも（P5・P6）確かめる。単体テスト、フレームのゴールデン、時間に関わる結合、上位（作品03）との契約を、1つの手順で回せる基盤が必要である。

## 決定

- **CMake＋CTest＋Unity（v2.7.0、submodule）** に一本化する。テストの実行ファイルは CMake のターゲットで、`ctest --preset host-debug` で全段（単体・ゴールデン・仮想時間シナリオ）を一度に動かす
- **Ceedling は使わない**。ビルドの定義が CMake と Ceedling の2か所に分かれ、ターゲット版（arm-none-eabi-gcc）とホスト版をプリセットで切り替える構成（NFR-09）と二重になるため
- **CMock も使わない**（P4 時点）。ポート（`ports/ports.h`）は関数ポインタの構造体なので、手書きのフェイク（`tests/fakes/fake_ports.c`）で差し替えられる。フェイクは状態を持つ（時刻・ADC の値・PWM の値・UART のバッファ・LED・ブザー・ボタン・ウォッチドッグのリフレッシュ回数）ので、呼び出しの順序を期待として書くモックより、シナリオの結合テストにそのまま使える。モックが必要なモジュールが出てきたら、そのとき CMock を入れる
- テストの段と役割：

| 段 | 何を確かめるか | 時間 | 手段 |
| --- | --- | --- | --- |
| 単体 | lib・service・app の各モジュールの境界・表の全行 | 引数で渡す | Unity＋手書きのフェイク |
| ゴールデン | フレームの符号化・復号が iot-common-spec v0.2.1 の参照と一致 | なし | `tools/gen_golden_vectors.py` が生成するテストベクタ |
| 仮想時間シナリオ | firmware 全体の時間に関わる要件（NFR-01 の2.5秒、承認の流れ、故障と復帰、上位断、ウォッチドッグの再起動） | 1ms ずつ進める仮想時間 | `tests/scenario/sim_harness` と CSV |
| 結合（ホスト版） | 実プロセスの再起動（execv）、pty 越しのフレーム、boot_id・seq・uptime の再開 | 実時間 | pytest（`tests/host_integration`）と iotspec の `FrameReader` |
| 契約 | 上位との約束（起動の順、ACK、重複、上位断、符号化、seq、変換後の JSON Schema） | 実時間 | `iotspec-contract --role mcu-c-01` |
| 品質ゲート | カバレッジ・MISRA・clang-tidy・複雑度・Doxygen・禁止項目 | — | `tools/quality.sh`（CI の quality ジョブ） |

## 理由

- 時間に関わる要件は、実時間で測ると CI の負荷で揺れる。仮想時間なら同じ入力で毎回同じ結果になり、境界（ちょうど2500ms、ちょうど3000ms など）を確かめられる
- 実時間は、上位との約束（契約テスト）と、プロセスの再起動のように仮想時間では模擬しきれないもの（pytest）だけに使う
- 1つのビルドシステムにまとめると、サニタイザー（host-debug）とカバレッジ（host-coverage）をプリセットの違いだけで切り替えられる

## 影響

- 新しいモジュールには、CMake の `tg_unit_test` でテストを1本足す。ポートを使うモジュールは `fake_ports` を広げて使う
- 時間に関わる要件のテストは、まず sim_harness のシナリオとして書く。実時間のテストを足すのは、仮想時間で模擬できない理由があるときだけにする
- 実機（P5）と Renode（P6）で確かめる項目（DWT の実測、IWDG、レジスタの値）は、この基盤の外（Robot Framework）で扱う
