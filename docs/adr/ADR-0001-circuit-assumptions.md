# ADR-0001 温度計測の回路の前提

- 状態：採用（2026-11-21）
- 関係する書類：詳細設計書 第3章、open-questions #20・#27

## 状況

ファームウェアは ADC の生値を温度（0.01℃ 単位の `int16_t`）に変換する。実機フェーズ（P5 以降）まで部品を実測できないので、変換表・故障の境界・ホスト版とシナリオの「温度 → 生値」を、仮の回路の前提から作る必要がある。

## 決定

- 回路：3.3V → 10kΩ（1%）プルアップ → ADC 入力 → NTC（10kΩ @25℃、B=3435）→ GND。ADC は12ビット、3.3V 基準のレシオメトリック。温度が上がるほど生値が下がる
- NTC の抵抗：R = 10kΩ × exp(3435 × (1/T − 1/298.15))（T は絶対温度）
- 生値：raw = round(4095 × R ÷ (R + 10kΩ))（open-questions #20）
- 変換表：−20〜120℃ を1℃ 刻みで141点。`tools/gen_ntc_table.py` がビルド時に `build/generated/ntc_table_data.h` を生成する。表の間は線形補間し、整数は四捨五入（負の値は 0 を中心に対称、#27）

| 温度 | NTC の抵抗（概算） | 生値 |
| --- | --- | --- |
| −20℃（表の端） | 77.5kΩ | 3627 |
| 25℃ | 10.0kΩ | 2048 |
| 120℃（表の端） | 0.62kΩ | 238 |

- 故障と範囲外：生値 < 50 は短絡、> 4045 は断線（3回連続で故障）。50〜237 は 120.00℃、3628〜4045 は −20.00℃ に丸める
- ホスト版と sim_harness の「温度 → 生値」（`bsp/host/ntc_model.c`）も同じ式を使う

## 理由

- 10kΩ の NTC と同じ値のプルアップは、25℃ で生値がちょうど中央（2048）に来て、測定範囲の両端でも分解能が残る、一般的な構成である
- B 定数の式は、データシートの表がない段階で使える近似として十分で、生成器が同じ式から表を作るので、ファームウェア・テスト・ホスト版の値がずれない
- 表を生成物にしておけば、実機で実測した点に置き換えるとき、生成器の入力を変えるだけで済む

## 影響

- 実機フェーズで部品の実測値に置き換える前提である。置き換えたら、生成器の検査（概算 3627・2048・238 から ±2 以内）と、故障の境界（49・50・4045・4046）・丸めの境界（237・238・3627・3628）のテストを見直す
- 置き換えのときは、この ADR を「置き換え済み」にして新しい ADR を足す
- B 定数の近似の誤差（高温側で大きい）は、この段階では精度の要件に入れていない
