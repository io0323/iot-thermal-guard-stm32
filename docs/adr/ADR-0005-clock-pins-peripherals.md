# ADR-0005 クロック・ピン・周辺機能の割り当て

- 状態：採用（2026-11-21）
- 関係する書類：要件定義・基本設計書 第6章（割り込み一覧）・FR-08・NFR-03・NFR-04、詳細設計書 第3章・第5章・第6章・第7章、open-questions #43〜#51、`bsp/stm32f4/pinmap.h`、`docs/isr-review.md`

## 状況

詳細設計書は、ピン割り当てやクロックの細部を「P5 で確定する」としていた。P5 のプロンプトで io が値を決め、P5 の作業中の未決（#43〜#49・#51）もこの表に反映した。実機（Nucleo-F401RE）では確かめていない。

## 決定

### クロックと時間

| 項目 | 値 |
| --- | --- |
| クロック | HSI 16MHz → PLL（M=16、N=336、P=4、**Q=7**）で SYSCLK 84MHz。VCO 336MHz、48MHz 系（PLL48CLK）は 48MHz（#43。USB・SDIO は使わないが、データシートの上限 48MHz に収める） |
| バス | AHB 84MHz、APB1 42MHz（タイマーは ×2 で 84MHz）、APB2 84MHz |
| Flash | 待ち 2WS、プリフェッチ・命令キャッシュ・データキャッシュを有効。電圧スケール 2（84MHz まで） |
| 外部クロック | 使わない。ST-LINK の MCO（HSE）には頼らない |
| SysTick | 1ms。tick_port の `now_ms` |
| DWT | CYCCNT を有効にして `cycles()` にする（スケジューラの計測、boot_id の材料） |

### ピン（すべて Arduino ヘッダに出ているピン、`bsp/stm32f4/pinmap.h`）

| 用途 | ピン | 機能 |
| --- | --- | --- |
| 温度（NTC の分圧） | PA0（A0） | ADC1_IN0（アナログ） |
| ファン PWM | PA6（D12） | TIM3_CH1（AF2） |
| UART | PA2（TX）・PA3（RX） | USART2（AF7）、ST-LINK の仮想 COM |
| LED 緑 | PA5（D13、基板の LD2） | GPIO の出力、High で点灯 |
| LED 黄 | PB4（D5） | GPIO の出力（リセット直後の NJTRST を GPIO にする。デバッグは SWD だけ） |
| LED 赤 | PB5（D4） | GPIO の出力 |
| ブザー | PB10（D6） | GPIO の出力、High で鳴る |
| ボタン | PC13（基板の B1、押すと Low） | GPIO の入力（基板のプルアップ）。割り込みは使わない（#48） |

### 周辺機能

| 項目 | 値 |
| --- | --- |
| 温度の取得 | TIM2 の TRGO（**PSC 839・ARR 999** で 100Hz）で ADC1_IN0 を変換。DMA2 Stream0 Channel0 で循環バッファ20語、半分転送・全転送の割り込みで「確定した半分」を知らせ、タスク側で10語を **(sum + 5) / 10**（四捨五入）で平均する（#44） |
| ADC | ADCCLK = PCLK2 ÷ 4 = **21MHz**（上限 36MHz）、12ビット、右詰め、サンプリング **480 サイクル**（約23μs。PA0・内部温度・VREFINT のどれも）（#44） |
| ADC の再起動 | `restart()` は TIM2・ADC・DMA を止め、フラグを消して初めから動かし直す（temp_sensor が無応答の300ms と、その後1秒ごとに呼ぶ） |
| ファン PWM | TIM3_CH1、PSC 0・ARR 3359 で 25kHz、PWM モード1、CCR = duty × 3360 ÷ 1000（1000‰ で CCR 3360 > ARR となり常に High）。起動時は100% |
| UART | USART2、115200・8N1、フロー制御なし、オーバーサンプリング16。RXNE で受信リング256バイト、TXE で送信リング128バイト。受信エラー（ORE・FE・NE・PE）はすべて SR → DR で消し、そのバイトはリングに入れる（#46） |
| IWDG | LSI（公称32kHz）を 1/32、リロード 500 で公称 500ms。bsp_init の最後に動かす |
| リセット要因 | RCC_CSR を起動時に1回読み、RMVF で消す。優先順は **IWDG → ソフトウェア → 電源投入 → BOR → 低電力 → ピン**（#51）。電源投入では BORRSTF とピンも立つので BOR より先に電源投入を見て、どのリセットでも立つピンは最後に見る。判定は純粋な関数 `bsp/stm32f4/reset_decode.c`（ホストの単体テスト `test_reset_decode`） |
| リセット回数 | `.noinit` にマジック値と一緒に置く。電源投入（またはマジック値が壊れている）なら 0、それ以外は前回 + 1（0xFFFF で止める） |
| boot_id の材料 | TIM2 を動かす前に、ADC をソフトウェア開始で使い、内部温度（ADC1_IN18）と VREFINT（ADC1_IN17）を32回ずつ読んだ値の下位4ビット（2回分を1バイトに）、DWT のサイクル数、UID（0x1FFF7A10 から96ビット）、RCC_CSR を並べる（52バイト）。CRC-32 で混ぜるのは service/boot_id |
| bsp の診断値 | `bsp_diag_port_t` の `read()` が `uart_ring_dropped`（受信リングが満杯で捨てたバイト）・`uart_errors`（受信エラー）・`stack_peak`（スタックの最大使用量）を返す。`rx_overflow`（フレームバッファのあふれ、#16）とは別の項目（#45〜#47） |

### 割り込みの優先度

NVIC の優先度グループは全ビットをプリエンプションにする（サブ優先度なし）。

| 割り込み | 優先度 |
| --- | --- |
| SysTick | 1 |
| DMA2_Stream0 | 2 |
| USART2 | 3 |

EXTI15_10（ボタン）は使わない（#48）。ISR ごとのレビューは `docs/isr-review.md`。

### メモリ

| 項目 | 値 |
| --- | --- |
| リンカスクリプト | `bsp/stm32f4/STM32F401RETx.ld`。FLASH 512K（0x08000000）、RAM 96K（0x20000000） |
| スタック | 4KB を RAM の先頭（0x20000000〜0x20001000）に置く。あふれると 0x20000000 より下の予約領域に当たり、BusFault から HardFault になり、IWDG でリセットされる（.data・.bss を壊さない） |
| スタックの塗り | main の最初に、今の SP より下を 0xA5 で塗る。最大使用量は塗られたまま残ったバイトから求めて `stack_peak` にする |
| ヒープ | 0。malloc 系と _sbrk を持ち込まない（`tools/check_size.py` が .map で確かめる） |
| 上限（NFR-04） | Flash 64KB、RAM 16KB（.data＋.bss＋.noinit＋スタック）。`tools/check_size.py` |

## 理由

- HSI だけで 84MHz を作ると、Nucleo の ST-LINK の MCO（はんだブリッジの設定に依存する）や外付けの水晶に頼らずに済む。UART の 115200bps は HSI の精度（±1%）で足りる
- ピンをすべて Arduino ヘッダに出ているものにすると、実機フェーズでシールドやジャンパー線だけで配線できる。緑の LED とボタンは基板のもの（LD2・B1）を使う
- **ボタンに割り込みを使わない理由（#48）**：チャタリング除去は「同じレベルが2回（20ms）続いたら確定」なので、10ms ごとのポーリングで足りる。割り込みで押下を拾っても、確定には2回の一致が要るので判定は速くならない。割り込みを1つ減らすと、ISR のレビューと最悪の入れ子が単純になる
- スタックを RAM の先頭に置くと、あふれたときに静かに変数を壊さず、必ず例外になる
- 診断値を `rx_overflow` に混ぜないのは、実機で「ISR のリングがあふれた」のか「フレームバッファがあふれた」のかを区別するため（#45）

## 影響

- 値はどれも実機で確かめていない。実機フェーズで、PWM の周波数と duty（オシロスコープ）、UART の通信、ADC の値と DMA の周期、IWDG の時間（LSI の個体差で 340〜940ms の幅）、スタックの最大使用量を確かめる
- ピンを変えるときは `bsp/stm32f4/pinmap.h` とこの表だけを直す
- 詳細設計書の写し（第1章の出力先、第2章の ports.h、第5章のボタン、第7章のリセット要因の優先順）と要件定義・基本設計書の写し（FR-08、割り込みの表）は、#48・#50・#51 と bsp_diag に合わせて直した（原本は io が更新済み）
